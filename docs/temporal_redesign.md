# Переработка метода: аудит и ограниченный пилот

Обновлено 27 октября 2026. Замороженный CIFAR-100N seed42 пилот проверен
на 10 000 чистых тестовых изображений без обучения и изменения политики:
база 69,79%, ученик 71,83% (+2,04 п.п.; парный интервал [1,46; 2,65]),
среднее пяти ранних моделей 73,15% (+3,36 п.п.). Ученик сохраняет 60,7%
прироста учителя при одном проходе backbone; уступает ему 1,32 п.п.
ECE ухудшился с 0,1226 до 0,1498, хотя NLL и Brier улучшились.
Все 46 проверок сырых предсказаний прошли. Источник и графики:
`outputs/temporal_test_import_20261027/`. Это одна база и одна голова;
интервалы условны на этих весах, без поправки на множественность.
Независимые повторы и сопоставимые нетемпоральные контроли ещё нужны.

## Что показал аудит

Проверены активный ResNet50-путь, загрузчики четырёх датасетов, построение целей,
разбиения, головы, выбор политик, метрики и компактные доказательные материалы.
Независимый аудит выполнил 2171 детерминированную проверку, связав 151 входной
файл с SHA256. В проверенной области не обнаружены существенная утечка чистых
меток, искусственное завышение метрик или ошибка выбора лучшего checkpoint.
Это не доказательство отсутствия любых ошибок: Mini-WebVision ещё требует
повторного расчёта из сырых предсказаний. Рецензии агентов относятся к одному
семейству моделей и остаются предварительными.

Найдена небольшая неточность статьи: размеры CIFAR были описаны как размеры
«каждого датасета». Область применения соответствующих абзацев уточнена.
Исторические результаты не переписывались.

## Почему текущий вклад может быть небольшим

1. **Ограничение места применения.** Early-5 меняет веса вероятностей нескольких
   аугментаций. При одном виде нормированный вес равен единице: ответ не меняется.
   Если все виды предпочитают один и тот же класс, их неотрицательная взвешенная
   смесь также не исправит этот класс. Это математическое ограничение интерфейса.
2. **Неполная цель.** В истории сохраняется margin только наблюдаемой метки.
   При применении голова получает предсказанный базой класс. Для ошибочно
   размеченных примеров условия обучения и применения могут различаться.
3. **Потеря конкурентов.** Один margin не сохраняет распределение остальных
   классов. Регрессионная MSE не равна полезности исправления классификации.
4. **Неизолированный эффект времени.** Первые пять эпох совпадают с CE warmup,
   а выбранная база часто относится к эпохе2/3. Нельзя приписывать весь эффект
   только временной истории. Слабое среднее History-50 не опровергает все способы
   представлять полную траекторию.
5. **Возможный предел информации.** В замороженных признаках выбранной базы может
   не остаться различий, которые были полезны ранним моделям. Более сложная голова
   не восстановит отсутствующую информацию автоматически.

Эти пункты — ограничения и гипотезы, а не найденные ошибки, исправление которых
обязано дать несколько процентных пунктов.

## Выбранное изменение

Сохраняем основную идею: информация обучения становится доступной на новых
изображениях без хранения всех ранних моделей при применении. Меняем передаваемый
объект и место подключения.

В **новом** базовом запуске сохраняются реальные веса после эпох1–5. После обучения
они обрабатывают одинаковые канонические тренировочные изображения в eval/FP32.
Для каждого изображения сохраняются вероятности **всех классов**, а не только
margin наблюдаемой метки. Цель `q` — среднее этих пяти распределений.

Небольшая голова получает замороженные 2048-мерные признаки выбранного ResNet50:
нормализация по meta-train → Linear(2048,256) → ReLU → Linear(256,K).
Последний слой начинается с нуля. Голова возвращает центрированную по классам
поправку `h`; итог:

```text
p_new = softmax(log(p_base) + alpha * h(features))
```

При `alpha=0` код возвращает исходные вероятности точно. При положительном alpha
может измениться сам класс даже для одного изображения. Цель обучения —
`KL(q || p_new(alpha=1))`, без чистых или наблюдаемых тренировочных меток в loss
головы. Наблюдаемые метки базовой валидации нужны только для выбора alpha.

Фиксированный первый рецепт: AdamW, lr0.001, weight decay0.0001, batch256,
25эпох, seed42; без PCA, TTA или размораживания backbone. Исходные meta-разбиения
60/10/15/15 сохранены: зарезервированные30% не превращаются скрыто в дополнительные
данные. Начальная нулевая голова тоже участвует в выборе checkpoint по минимуму
meta-validation KL. Alpha выбирается из `[0,.25,.5,1]`: noisy-validation accuracy,
затем меньшая CE, затем меньший alpha.

При точном восстановлении цели это геометрическая интерполяция исходного
распределения и среднего ранних моделей. **Это пока пилот сжатия ансамбля
снимков, а не доказанная новая научная методика.** Ранние учителя и дистилляция
уже исследованы: [Snapshot Distillation](https://arxiv.org/abs/1812.00123),
[Temporal Ensembling](https://arxiv.org/abs/1610.02242),
[self-distillation при шуме меток](https://proceedings.mlr.press/v202/das23d.html).
Сильная статья потребует отдельного механистического результата и сравнений.
Две рецензии предложения оставили вердикт REVISE; это не объявление готовности
к публикации.

## Что реализовано

- Опциональные ранние checkpoints с эпохами, конфигурацией и SHA256. Они не
  заменяют `best.pt`, выбранный по noisy-validation CE.
- Новый базовый рецепт откладывает доступ к чистому тесту до фиксации всей
  последующей политики; старые рецепты сохраняют прежнее поведение.
- Отдельные стадии сбора доказательств, обучения и финальной оценки. Массивы
  извлекаются пакетами на диск; проверяются ID, классы, разбиения и хеши.
- На валидации доступны настоящий средний учитель и его интерполяция с базой:
  можно отличить бесполезный учитель от неудачного переноса в голову.
- Финальная оценка сравнивает одношаговую базу и ученика, а также дорогой
  пятишаговый учитель. Подмена ранних весов после обучения отвергается.
- Прерванная финальная оценка повторяется только с тем же зафиксированным
  контрактом; завершённый экспорт защищён от перезаписи.
- Сохраняются config, metrics, metadata, отчёт, полные предсказания и компактная
  таблица. AUROC собственных ошибок отделён от AUROC исходных ошибок базы.

Голова сейчас не возобновляет оптимизатор: незавершённое короткое обучение
повторяется с новым run_id. База возобновляется по существующему протоколу;
сбор кэша после прерывания повторяет незавершённые проходы. Это не обещание
побитного воспроизведения между разными GPU/версиями библиотек.

## Порядок следующего исследования

1. **Один новый пилот**, сначала noisy-validation. Достаточно CIFAR-100N seed42;
   проверяется новый интерфейс, поэтому это не новая независимая репликация
   исторической оценки. Старые scalar-файлы не содержат всех вероятностей классов:
   восстановить из них отсутствующие веса эпох1–5 невозможно.
2. Сравнить базу, реальный ранний учитель и ученика. Если интерполяция учителя
   не улучшает noisy-validation accuracy, нет основания сразу запускать остальные
   seed. Положительный alpha при равной accuracy и меньшей CE означает только
   улучшение этого калибровочного критерия. Если учитель помогает, а ученик нет,
   исследуем переносимость сигнала и KL на не виденной базой валидации.
3. **Позже, как согласовано:** два решающих контроля — обучаемое нетемпоральное
   объединение при том же бюджете и разделение эффекта истории от CE/GCE/раннего
   checkpoint. Добавить одинаковую residual-голову, обученную CE по noisy меткам,
   и один ранний snapshot как сравнения. Дистилляция `p_base` сама в `p_base` —
   лишь нулевая техническая проверка, не сильный контроль ёмкости.
4. Только при положительном и объяснимом пилоте — три независимые базы и перенос
   на внешний датасет. Уже просмотренные тесты остаются exploratory. Число seed,
   доверительные интервалы и поправки на множественный выбор не заменяются
   красивым средним по головам.

Обучение новой базы остаётся основной стоимостью; дополнительно нужны пять
канонических проходов по train/validation и около500MB для ранних весов.
Время нового пути на T4/L40 ещё не измерялось. Оснований обещать конкретный
прирост или точное ускорение от двух L40 пока нет. До проверки полезности учителя
расширять GPU-кампанию преждевременно.

## Как запустить из этой рабочей копии

Ниже исходный шаблон команд. Первый пилот уже выполнен26октября через отдельный
ноутбук с зафиксированным архивом исходников; для следующего шага нужны его
полные Output с весами и кэшем. Повторять обучение базы сейчас не требуется.
Новый код пока не отправлен в GitHub; старый опубликованный commit его не содержит.
Пути к данным следует заменить на фактически подключённые пути Kaggle.

```bash
python scripts/run.py train-kaggle-base --config-name temporal_base \
  data_dir=/kaggle/working/rfd_data \
  output_dir=/kaggle/working/rfd_temporal_bases

python scripts/run.py distill-temporal stage=prepare \
  source_run=/kaggle/working/rfd_temporal_bases/temporal_cifar100n_seed42_v1 \
  data_dir=/kaggle/working/rfd_data \
  cache_dir=/kaggle/working/rfd_temporal_cache \
  output_dir=/kaggle/working/rfd_temporal_heads

python scripts/run.py distill-temporal stage=fit \
  cache_dir=/kaggle/working/rfd_temporal_cache \
  output_dir=/kaggle/working/rfd_temporal_heads
```

Сначала изучается отчёт `temporal_residual_seed42_v1/report.md` и таблицы
`validation_policies.csv` / `validation_teacher_interpolation.csv`. Флаг
`pilot_diagnosis` — описательная диагностика noisy-validation, не статистическая
значимость. После принятия решения фиксированная политика оценивается отдельно:

```bash
python scripts/run.py distill-temporal stage=evaluate \
  source_run=/kaggle/working/rfd_temporal_bases/temporal_cifar100n_seed42_v1 \
  data_dir=/kaggle/working/rfd_data \
  cache_dir=/kaggle/working/rfd_temporal_cache \
  output_dir=/kaggle/working/rfd_temporal_heads
```

Локальная проверка без скачивания датасетов и обучения ResNet50:

```bash
python -m pytest -q tests/test_temporal_residual.py tests/test_kaggle_base.py
```

Синтетические тесты доказывают свойства кода и границы доступа к данным;
они не являются научными результатами на перечисленных датасетах.
