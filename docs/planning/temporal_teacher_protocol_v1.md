# Контроль истории обучения при прямой дистилляции

Статус: дизайн зафиксирован до оценки на CIFAR-10.2. Для запуска нужно
подключить полные S4 Outputs, проверить их манифесты и собрать контрольные
головы. CIFAR-10.1 использовался для предыдущей проверки. Его результат
мотивирует этот эксперимент и остаётся частью отчёта S4.

## Вопрос и сравнение

Даёт ли среднее пяти ранних состояний более полезные цели для прямой
дистилляции, чем пять прогнозов одной ранней модели на разных версиях
того же изображения? На CIFAR-10.1 прямая голова показала +0,57 п.п.
против базы во вторичном сравнении. Этот результат сам по себе не измеряет
вклад истории.

- **Early-5 direct.** Среднее вероятностей чекпойнтов эпох 1–5 на исходной
  картинке. Используем замороженную прямую голову из S4.
- **Static-5 direct, основной контроль.** Выбираем один чекпойнт из эпох
  1–5 по точности его канонического прогноза на noisy-val. При равенстве
  выбираем меньший NLL, затем более раннюю эпоху. Для этого чекпойнта
  усредняем вероятности пяти фиксированных представлений каждой картинки.
  Представления строим на 32×32 до общего преобразования ImageNet: исходное,
  отражение по горизонтали, сдвиг на два пикселя вправо, влево и вниз.
  Пустую границу заполняем отражением без повторения крайнего пикселя.
  Все веса равны 1/5. Рецепт представлений общий для всех баз.
- **Дополнительные сравнения.** База без головы, прямая голова от выбранного
  одиночного снимка на исходной картинке и два несжатых учителя. Одиночный
  снимок показывает, что изменилось за счёт усреднения относительно
  выбранного чекпойнта. Несжатые учителя показывают, где возникает
  разница: в целях либо при их переносе в голову.

Оба основных учителя выполняют пять проходов на пример при получении
обучающих целей. У обоих учеников один проход ResNet50. Учителя используют
разные источники разнообразия: веса либо преобразования изображения.
Вывод ограничен этими рецептами. Сравнение не изолирует порядок эпох и не
уравнивает накладные расходы на выбор чекпойнта и подготовку представлений.

## Протокол

Используем те же три независимые базы CIFAR-10N Worse (42, 43, 44), их ранние
снимки и фиксированные noisy train/val и meta-разбиения. У прямых голов
одинаковы замороженные признаки, 2048→256→10, AdamW, 25 эпох, batch 256,
lr 0.001, weight decay 0.0001, seed 42, KL при T=1. Выбор головы по meta-val
KL, включая эпоху 0. Смешивание с базой использует ту же сетку alpha
{0, 0.25, 0.5, 1} и то же правило noisy-val accuracy, затем меньший NLL,
затем меньший alpha. Чистые тестовые метки появляются только на этапе оценки.

Выбранная внешняя выборка — официальный тест [CIFAR-10.2](https://github.com/modestyachts/cifar-10.2/blob/master/cifar102_test.npz),
2 000 изображений. Авторы [описали фильтрацию точных и близких дубликатов
относительно CIFAR-10 и CIFAR-10.1](https://www.gatsby.ucl.ac.uk/~balaji/udl2020/accepted-papers/UDL2020-paper-101.pdf).
Версия файла закреплена по метаданным GitHub: tree
`521467a52ad494b78ff9c70051099c0d9ba74d40`, blob
`7a3829681be56af70ea80ec99cf3822e2f5edff3`, 6 393 664 байта.
При финальной загрузке сверяем Git blob, сохраняем SHA-256 и проверяем
размеры, типы, порядок
классов, баланс, уникальные ID и точные совпадения пикселей с CIFAR-10
train/test и CIFAR-10.1 v6. При нарушении контракта останавливаем оценку до
подсчёта метрик. Локальный поиск не нашёл прежних прогонов CIFAR-10.2 в
исходниках и материалах статьи. Автоматическая проверка дубликатов касается
доступных наборов, а не всего корпуса предобучения ImageNet.

Основное сравнение — **Early-5 direct минус Static-5 direct**, среднее
по трём базам на одних и тех же изображениях. Заранее заданный порог —
средний выигрыш ≥ 0,50 п.п. и нижняя граница парного 95% интервала > 0.
Используем 10 000 стратифицированных повторов, seed 20261015, одинаковые
ID в каждом повторе для всех методов и баз. Интервал условен на обученных
весах; отдельно публикуем три разности и их выборочное SD. Для вывода о
практическом выигрыше также отдельно требуем положительную нижнюю границу
сравнения с исходной базой. Остальные сравнения, NLL, Brier, ECE и AURC
отмечаем как вторичные, интервалы для них номинальные.

## Порядок выполнения

1. Проверить хеши трёх S4 манифестов, ранних снимков, базы и прямой головы.
   Для кэша требовать совпадение ID, разбиения, размеров и источника.
   При недоступности кэша восстанавливаем признаки и цели из снимков.
2. Подготовить цели, обучить только контрольные головы, выбрать alpha на
   noisy-val и записать конфиги, хеши, политики, время расчёта целей и головы.
   Сохранить замороженный комплект на каждую из трёх баз.
3. Отдельным запуском проверить все комплекты и открыть CIFAR-10.2.
   Экспортировать метрики и предсказания для парного пересчёта.
   Число баз и основное сравнение остаются заданными этим протоколом.
