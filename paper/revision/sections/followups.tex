\section{Follow-up Target Controls}
\label{app:followup_controls}
The follow-up covers CIFAR-100N base seeds 42/43/44 and CIFAR-10N Worse base seed43; the planned CIFAR-10N base42 control remains blocked by missing verified study inputs. It reuses frozen base features, the original train-only PCA, and the nine existing base-feature heads per base. Three new heads per base predict the mean observed-label margin over five augmentations at the minimum-noisy-validation-loss checkpoint. The transform is the actual base-training sequence: constant-padding random crop at $32\times32$, random horizontal flip, then ImageNet resize/normalization. This differs from the reflected-padding inference-view stream. Original training RNG draws were not recorded; the control samples new deterministic draws (seed 20261019). It neither matches online weight evolution nor separates the cross-entropy warmup from later GCE training.

All old validation-selected policies and downstream accuracy values reproduce. New policies freeze before test evaluation; clean training labels do not construct targets or fit heads. The four completed augmentation controls together fit twelve new heads; no base is retrained. The first two-base follow-up batch, including direct comparisons and runtime measurements, takes 41.89 minutes. The additional CIFAR-100N base42/43 paired/augmentation stages total 40.68 minutes, excluding initial input inspection and cache recovery. Neither duration is the cost of one deployment head.

The base42 shared cache was unavailable in the mounted historical Output. Its replacement reuses the already recorded native FP32 probability arrays with the same base digest, sample IDs and deterministic views, without new inference or fitting. Recovery required the original alignment records to report zero per-view prediction disagreements and reproduced all 93 saved validation/test selected-policy accuracies. Native probabilities are not claimed bit-identical to the old shared cache. Learned-head AUROC agrees with earlier compact evidence; nonlearned original-view AUROC differences from earlier snapshots are at most $1.20\times10^{-7}$. Raw arrays and weights are absent from the compact export, so the present import verifies saved metadata and table arithmetic rather than independently recomputing the bootstrap intervals.

\section{Matched Inference Microbenchmark}
\label{app:runtime}
A single Tesla T4 session runs sequentially on CIFAR-100N base44 and CIFAR-10N base43 using PyTorch 2.11.0+cu128, FP32 and four CPU threads. Head seed42 is fixed. Each timing configuration uses five warmups and 30 synchronized repetitions. Batch sizes 1/4 and view counts 1/5/10 are predefined; images are the first four fixed noisy-validation IDs, with shared deterministic view prefixes. Neither accuracy nor labels select timing cases. Temperatures come from each saved view budget's validation policy, rather than the globally selected view count. This reference inference path fuses the selected base features, PCA and the scalar head; cache generation and model/disk loading are outside the timing scope.

Table~\ref{tab:runtime} reports batch-size-one medians. The model scope starts from device tensors; the preprocessing scope includes CPU view generation, normalization and host-to-device transfer. Full CSVs retain batch medians/p95, batch-four amortized cost and GPU allocation measurements. Batch-four p95 is not per-image p95. Peak MB means PyTorch-allocated CUDA memory in decimal MB, not total device memory. Uniform/single-view policies skip the head.

At five/ten views the observed extra allocated peak memory is about 4.8 MB for the PCA/head. Multi-view prediction is substantially costlier than a one-view base pass. Close matched-view medians are preliminary: one session, a fixed measurement order, a tiny fixed image set, and no independent timing intervals preclude a precise overhead guarantee. Separate one-view cases using equivalent computations also exhibit timing variation. No two-base ensemble is timed. These results do not establish lower latency than an ensemble or the cost of separately returning a standalone error-ranking score for every image.
